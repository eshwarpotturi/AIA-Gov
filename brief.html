Maker-checker for AI agent permissions

AI proposes, Compliance approves, code enforces, and every attack makes the rules stronger.

Live demo: the $2M question, replayed.

The problem

A bank with 160+ systems already has AI agents working across them, but no central control over which agent may do what, on whose behalf. When a trader asks an assistant “why does my desk show a $2M discrepancy?”, the assistant needs trades, positions, prices and risk from four systems. The trader may see his own desk's trades but not another desk's confidential positions or clients. The agents must keep those restrictions even when they combine information. Agents usually run on broad service accounts, so without this control an agent becomes a back door.

The design: three layers

Traderasks one question; his identity rides on every call
Orchestrating agentalways in the path; asks Trade, Position, Market Data, Risk agents
The Gate (code)every call: agent mandate ∩ human entitlement → allow / filter / deny / hold for human. No LLM, fails closed.
Governance agentexceptions only: drafts the mandates, grants narrow task-scoped exceptions, isolates rogue agents, proposes rule fixes; also loosens rules that are too tight for routine work
Auditor agent + Compliancethe Auditor probes freely; findings are verified by code; Compliance approves every rule version (a person, in live mode)

This answers the “one overarching agent vs rules” question: both, at different layers. The Orchestrator coordinates; deterministic rules decide; the governing AI only handles exceptions and never widens access on its own. An LLM in the enforcement path could be talked into “yes”, so enforcement stays in code.

Limits

  • Synthetic data and fictional clients; one trader, two desks, four systems. It demonstrates the method, not coverage of 160+ systems.
  • The Auditor runs agents in an explicit “assume compromised” mode, because a control has to hold even when the agent misbehaves.
  • Control-testing agents add to human penetration testing; they don't replace it.
  • The default page is a replay of one recorded real run (GPT-4.1-mini via Straive LLM Foundry); the same floor also runs live on a laptop.
  • All eight agents are real (system prompt, tools, tool-calling loop; definitions in agents/*.json). Scripted: the trader's one question, the labelled injected-instruction test, and the triggers that wake control agents. The Compliance agent stands in for a human; in live mode a person approves.
